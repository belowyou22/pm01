# Чек-лист Модуля 3 — Оптимизации и анимации

## 1. Доработка базы данных

### Новые сущности
- [x] Таблица `order_status_history` — история смены статусов заявок
- [x] Связи: `order_id → orders.id`, `status_id → statuses.id`, `changed_by → users.id`
- [x] `ON DELETE CASCADE` для заявок, `ON DELETE RESTRICT` для статусов и пользователей

### Индексы
- [x] `idx_history_order` — быстрый поиск истории по заявке
- [x] `idx_history_created` — сортировка по дате
- [x] `idx_history_order_created` — составной (заявка + дата DESC)
- [x] `idx_orders_user_status` — фильтр заявок пользователя по статусу
- [x] `idx_orders_status_created` — фильтр по статусу и дате
- [x] `idx_orders_category_created` — фильтр по категории и дате
- [x] `idx_orders_fulltext` — FULLTEXT-поиск по названию и описанию

### Ограничения
- [x] `chk_orders_price` — цена не может быть отрицательной
- [x] `chk_orders_title` — название не короче 3 символов
- [x] `chk_orders_category` — категория не пустая

### Миграция
- [x] `database/schema_v2.sql` — применяется поверх `schema.sql` без потери данных
- [x] Автомиграция существующих заявок в историю (первичная запись)

## 2. Интеграция фронта и бэка

### Смена статуса заявки
- [x] `api/admin.php` — при смене статуса пишется запись в `order_status_history`
- [x] Транзакция — обновление статуса + запись в историю атомарны
- [x] `changed_by` — ID админа из сессии (не автора заявки)
- [x] Автокомментарий: «Статус изменён на «Х»», если админ не ввёл свой текст
- [x] Проверка: если статус не изменился — запись не создаётся (защита от дублей)

- [x] Модальное окно «📜 История» в `user-dashboard.html`
